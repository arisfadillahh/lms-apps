# Error Fixing Log - August 2026

## INTERNAL-20260812-01 Ekskul lesson editor loaded the wrong record

- Symptom: editing a lesson such as Scratch 13 could show the title and fields from another lesson or plan.
- Root cause: modal state depended on stale component props and reused component identity while the selected plan changed.
- Changed: `EditEkskulLessonButton.tsx`, `EkskulSplitViewClient.tsx`, `/api/admin/ekskul/lessons/[id]`, `EditEkskulPlanButton.tsx`, and `/api/admin/ekskul/plans/[id]`.
- Fix: reset form state on open, fetch the selected lesson by its immutable ID, validate `planId` server-side, and key editor components by lesson/plan ID.
- Preserve: edits and deletes must always be scoped to both the immutable record ID and its current plan. Do not restore prop-only modal initialization.
- Verification: TypeScript and production build passed; production endpoint and PM2 were healthy after deployment.

## INTERNAL-20260812-02 Admin users page schema crash

- Symptom: `/admin/users` could not load.
- Root cause: extending a refined Zod schema with `.extend()` caused a runtime failure.
- Changed: `src/app/(admin)/admin/users/CreateUserForm.tsx`.
- Fix: use `.safeExtend()` for the active-state field.
- Preserve: coder-specific cross-field validation in the base schema must remain active.
- Verification: TypeScript and production build passed.

## INTERNAL-20260812-03 Story overlay scroll lock on iOS

- Symptom: trial/weekly story content was cropped on iPhone and swiping scrolled the report behind the overlay.
- Root cause: only the overlay was constrained; the document body remained scrollable and mobile viewport units were unstable.
- Changed: `TrialStoryReport.tsx`, `ReportStoryExperience.tsx`, and `ReportStoryExperience.layoutFix.ts`.
- Fix: lock `html` and `body`, preserve/restore scroll position, use stable mobile viewport sizing, and keep overflow inside the active slide.
- Preserve: cleanup must restore all original document styles when the story closes or unmounts.
- Verification: responsive source checks, TypeScript, and production build passed.

## INTERNAL-20260812-04 Admin modal actions clipped on small viewports

- Symptom: edit lesson/plan and permanent schedule modals were clipped above or below a small browser window, making actions inaccessible.
- Root cause: fixed backdrops forced vertical centering while modal height exceeded the viewport.
- Changed: `EditEkskulPlanButton.tsx`, `EditEkskulLessonButton.tsx`, and `ChangeClassScheduleModal.tsx`.
- Fix: align modals from the visible top edge, add safe-area padding, cap height with `100svh`, enable contained scrolling, and wrap fields/actions.
- Preserve: new long modals should use the same viewport-safe pattern and must not rely on `alignItems: center` without overflow handling.
- Verification: TypeScript, `git diff --check`, production build, route smoke check, and PM2 status passed.

## INTERNAL-20260812-05 Permanent class schedule change

- Symptom: admins could change one session but not the recurring schedule for the remainder of a class.
- Root cause: no class-level operation propagated a new weekday/time to future scheduled sessions.
- Changed: `ChangeClassScheduleModal.tsx`, `/api/admin/classes/[id]/schedule`, and the admin class detail page.
- Fix: update class schedule metadata and only future sessions still in `SCHEDULED` status, preserving completed/cancelled history.
- Preserve: never move completed, cancelled, or otherwise historical sessions during a recurring schedule change.
- Verification: TypeScript and production build passed; route was generated in Next.js output.

## INTERNAL-20260812-06 Coach and Coder issue reporting

- Symptom: Coach and Coder had no structured way to submit LMS errors with screenshots and reproducible context.
- Root cause: reports were handled informally and had no durable database record linked to admin troubleshooting.
- Changed: `issue_reports` migration/types, `/api/issue-reports`, global `IssueReportButton`, admin `/admin/issue-reports`, storage helper, WhatsApp image helper, role layouts, admin navigation, and this documentation.
- Fix: add authenticated report submission with title, description, optional screenshot, optional user-entered related page, automatic user-agent/viewport capture, admin status and resolution workflow, and WhatsApp notification to the configured issue number.
- Preserve: database persistence is authoritative; storage or WhatsApp failure must never delete or reject a valid report. If screenshot storage fails, the in-memory image is still sent to WhatsApp and the user receives a warning. Screenshot types are limited to PNG/JPEG/WebP and 5 MB. Technical Markdown must not contain sensitive report contents.
- Verification: linked Supabase migration applied; 5 focused unit tests, TypeScript, local and production builds passed; unauthenticated API requests return `401`; the protected admin route redirects to the healthy `/login` page; PM2 restarted online. The WhatsApp delivery path reuses the production Baileys sender and was not exercised with a dummy report to avoid sending a false alert. The related-page field is manual and optional; blank input is omitted from the WhatsApp message rather than guessed from the current browser URL.

## INTERNAL-20260812-07 Admin issue reporting

- Verification: migration applied to the linked Supabase project; 6 focused tests, TypeScript, production build, and production smoke checks passed. `/login` returned `200`, unauthenticated `/api/issue-reports` returned `401`, and PM2 was online after restart.

## INTERNAL-20260812-08 PWA push fallback for WhatsApp logout

- Symptom: WhatsApp logout cannot notify the team through WhatsApp itself.
- Root cause: there was no device notification channel tied to an authenticated LMS account.
- Changed: PWA manifest/service worker, per-user push subscription migration/API, admin notification controls, and WhatsApp auth-disconnect handling.
- Fix: admins can install the LMS and activate web push. Auth-related WhatsApp disconnects create an internal admin notification and send a push notification to each subscribed active admin. Stale push subscriptions are removed on `404/410` delivery responses.
- Preserve: manual WhatsApp disconnect and force reset do not generate a false logout alert; the existing internal notification bell remains the fallback when push permission is unavailable.
- Verification: pending migration, VAPID environment setup, focused tests, TypeScript, production build, and mobile smoke checks.
