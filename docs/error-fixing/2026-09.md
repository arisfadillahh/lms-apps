- **Verification:** Portfolio responsive contract passed 5 tests, clean-source `npx tsc --noEmit` passed, and `git diff --check` passed. Next webpack compiled successfully before the pre-existing unrelated Coach Ekskul `PageProps.params` type-generation error. The CTA glow was also reduced to a smaller shape-aware drop-shadow so it cannot read as a clipped rectangular patch.
- **Invariants preserved:** Other Admin, Coach, and Coder mobile scroll behavior remains unchanged. Portfolio layout, color palette, content, published data, modal behavior, and database/API state are unchanged.
- **Regression risks:** Global mobile overflow rules must continue to exclude `data-portfolio-page="true"`; future public pages should use their own scroll mode marker if they need different document behavior.
- **Verification:** Portfolio responsive contract passed 5 tests, clean-source `npx tsc --noEmit` passed, and `git diff --check` passed. Production touch QA at 390x844 will verify one `HTML` scrolling context, one document width, and CTA filter after the release is deployed.

## INTERNAL-20260901-04: Portfolio body overflow axis normalization

- **Date / reference:** 2026-09-01 / `INTERNAL-20260901-04`.
- **Symptom:** Two vertical scrollbar tracks were still visible on desktop at the user's browser size and zoom after entering the public Portfolio experience.
- **Root cause:** The page-specific rule only set `body` vertical overflow to `visible`, while the global stylesheet kept horizontal overflow `hidden`. CSS overflow-axis normalization converts `visible` on one axis to `auto` when the other axis is `hidden`, so both `HTML` and `BODY` remained independently scrollable when body content exceeded its client height.
- **Changed:** `src/components/portfolio/PublicPortfolioExperience.module.css`, `src/lib/__tests__/publicPortfolioResponsive.contract.spec.ts`, and this log.
- **Fix:** The Portfolio page now restores both body overflow axes to `visible`; `HTML` remains the sole vertical scrolling element. Horizontal clipping remains owned by the Portfolio root wrapper, so the layout does not gain horizontal overflow.
- **Invariants preserved:** Portfolio layout, motion, intro lock, modal lock, data, API state, and all non-Portfolio role pages remain unchanged. No database changes are required.
- **Regression risks:** Any future global overflow declaration must not turn Portfolio body overflow back into an independent scrolling context.
- **Verification:** Portfolio responsive contract passed 5/5 tests, clean-source `npx tsc --noEmit` passed, and `git diff --check` passed. Production browser QA at 1873x963 confirmed body overflow is `visible` on both axes, the only vertical scrollable element is `HTML`, document width equals viewport width, a scroll interaction moved the document from 0 to 688 px, and no console warnings or errors were emitted.
- **Deployment:** Release `5165db521425a035b7d185877ab90c193eaee8e6` was deployed through `/root/lms/deploy-production.sh`; rollback target is `99bb044bf0d553baf6e5812a7983c196eba69eb3`. PM2 and public route smoke checks are recorded after the final documentation release.

## BUG-2D2206B: Permanent class reschedule collapsed lessons onto one date

- **Date / reference:** 2026-09-01 / `BUG-2D2206B`.
- **Symptom:** On the Admin class detail page, permanent rescheduling could place several upcoming Creator lessons on the same date. The affected Coach Naufal Saturday classes showed multiple lessons competing for one session date.
- **Root cause:** The permanent schedule endpoint snapped every future session independently to the requested weekday. Sessions that were already in the same calendar week therefore collapsed onto one timestamp. Equal timestamps had no curriculum-order tie breaker, and weekday calculation used UTC instead of the class's WIB calendar date.
- **Changed:** `src/app/api/admin/classes/[id]/schedule/route.ts`, `src/app/(admin)/admin/classes/[id]/ChangeClassScheduleModal.tsx`, `src/lib/services/classScheduleReflow.ts`, `src/lib/__tests__/classScheduleReflow.spec.ts`, and this log.
- **Fix:** Future scheduled sessions are now ordered by their existing date and assigned lesson curriculum order, aligned using the WIB calendar weekday, and reflowed into strictly increasing weekly slots. Existing multi-week gaps are retained. The Admin confirmation copy now states that lesson order remains intact and only one meeting is scheduled per week.
- **Invariants preserved:** Only future `SCHEDULED` sessions in the selected class are updated. Completed/cancelled history, session IDs, lesson assignments, class blocks, global lesson templates, other classes, coach assignment, and database schema remain unchanged. Existing notification delivery after a permanent schedule change is preserved.
- **Regression risks:** Future changes to class lesson ordering must keep `class_block.start_date` and `class_lesson.order_index` available to the reflow. A class that intentionally needs more than one meeting on the same weekday must use a separate explicit workflow instead of this weekly recurring-schedule action.
- **Verification:** Focused reflow tests passed 4/4, and the full suite passed 294/294 tests across 66 files. `npx tsc --noEmit`, `git diff --check`, and the production build with non-secret build placeholders passed. The scoped repair changed eight future sessions across the two affected Creator Saturday classes and verified zero duplicate scheduled timestamps afterward. Production serves `/login` with HTTP 200, signed-out access to the affected Admin class redirects to login, and PM2 `lms` plus `clevio-wa` are online. Recent retained PM2 error history contains pre-existing outbound fetch timeouts, stream closures, and a Node deprecation warning; no class-schedule error appeared after deployment.
- **Deployment:** Release `aaf208c1ec1ed9f18ce818c07b1c2e39e266fad0` was deployed through `/root/lms/deploy-production.sh`; rollback target is `3e5f8c8f6cb4eaecca2949e96472df9ac81af033`. Before the scoped repair, the eight original timestamps were stored in `/root/lms/shared/bugfix-backups/BUG-2D2206B-1788259066007.json`. The issue report was marked resolved and the requested WhatsApp completion report was delivered successfully.

Future lessons can still adopt content, order, and meeting-count changes, after which only scheduled future assignments are rebuilt. Saving a lesson automatically publishes its block, and the additive migration publishes existing blocks that already contain active lessons.

A lesson A duration edit cannot rewind a class already teaching lesson B. Changes remain scoped to classes linked to the edited global block; other classes and global templates are untouched.
